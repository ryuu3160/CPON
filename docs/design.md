# 設計書: CPON テキスト形式(.cpon)の読み書き

状態: 確定
更新日: 2026-11-16

## 目的と成功の条件
- `.cpon` テキスト形式で、書いたデータが必ず同じ内容で読み戻せるようにする。使うのは CPON を参照する ForgeX。
- 成功の条件
  - 次の5つがテストで通る: ネストしたオブジェクトの複数ブロック / 最後以外のブロックで末尾キーが欠ける場合 / `,` を含む文字列配列 / 改行を含む文字列 / 壊れたファイルで `false`(例外を出さない)。
  - v1.4.x までが書いた `.cpon`(版数なし)で、今読めているものは同じ内容で読める。
  - 既存のテスト22件が通る。
- やらないこと
  - バイナリ形式(`.cponb`)の変更。
  - 公開 API の変更(`GetValue` の戻り値など)。`cpon` クラスの公開メンバー関数は増減しない。
  - 新形式のファイルを旧バージョンの CPON で読めるようにすること。
  - キー名・オブジェクト名に含まれる特殊文字(`:` `,` `[` `{` 改行)への対応。

## 部品
### cpon_text_helper(新規、内部用: `CPON/src/cpon_text.hpp` / `cpon_text.cpp`)
- 何をするか: オブジェクトの並びをテキスト形式で書く。テキストを読んでオブジェクトの並びを作る。版数を見て、新形式(v2)と旧形式(v1)の読み方を切り替える。
- どう使うか:
  ```cpp
  class cpon_text_helper
  {
  public:
      // 常に v2 で書く。ストリームへの書き込みに失敗したら false
      [[nodiscard]] static bool Write(std::ostream &In_Out, const std::vector<std::shared_ptr<cpon_object>> &In_Objects);
      // 成功したら Out_Objects を読んだ内容で置き換えて true。失敗したら Out_Objects に触らず false。例外を外に出さない
      [[nodiscard]] static bool Read(std::istream &In_In, std::vector<std::shared_ptr<cpon_object>> &Out_Objects);
  };
  ```
- 何に依存するか: `cpon_object.hpp`(`cpon_block` と `cpon_object` の friend にする。`cpon_binary_helper` と同じ形)、`cpon_hints.hpp`。
- 公開ヘッダーではない。NuGet パッケージの `include/` にはコピーしない。

### cpon_hints(新規、内部用: `CPON/src/cpon_hints.hpp`、ヘッダーのみ)
- 何をするか: ヒント文字列(`Name:string,Scores:array<int>,Addr:object`)を、キーと型の並びに分解する。今は4か所に同じ処理がある。
- どう使うか:
  ```cpp
  namespace cpon_detail
  {
      struct HintEntry { std::string Key; std::string Type; };
      // 「:」の無い項目、キーが空の項目があれば false。空文字列は成功(0件)
      [[nodiscard]] inline bool ParseHints(std::string_view In_Hints, std::vector<HintEntry> &Out_Entries);
  }
  ```
- 使う場所: `cpon_text_helper`(読み書き)、`cpon_binary_helper::SerializeObject`。

### cpon(既存、`cpon.hpp` / `cpon.cpp`)
- `WriteToFile` / `LoadFromFile` は、拡張子の補完とファイルを開くことだけを行い、中身は `cpon_text_helper` に任せる。
- テキスト用の非公開メンバー(`ReadObject`、`WriteDataBlocks`、`ToStr`、`FromStr`、`m_FileHeader` など)は `cpon.hpp` から消す。

## データの流れ・状態
- 書く: `cpon::WriteToFile` → `std::ofstream` → `cpon_text_helper::Write`。インデントは、書き込み時の再帰の深さで決める(`m_NestedLevel` は見ない)。
- 読む: `cpon::LoadFromFile` → `std::ifstream` → `cpon_text_helper::Read`。全行を先に `std::vector<std::string>` に読み、位置を進めながら解析する(先読みができる)。結果は一時的な並びに作り、成功したときだけ `m_Objects` と入れ替える。

### v2 の形式
```
#ObjNum : 1 #Version : 2
Person[2]{Scores:array<int>,Address:object,Name:string}:
  Scores:[3]85,90,95
  Address:[2]{City:string}:
    City:New York

    City:Osaka
  Name:Alice\nSmith

  Name:Bob

```
- 1行目: `#ObjNum : <オブジェクト数> #Version : 2`。
- オブジェクト: `<名前>[<ブロック数>]{<ヒント>}:`。ネストしたオブジェクトは `<キー>:[<ブロック数>]{<ヒント>}:`。
- ブロックの各行: 深さ d(最上位のオブジェクトのブロックが d=1)に対して、半角空白 2×d 個、`<キー>:<値>`。ヒントの順に書き、そのブロックに無いキーの行は書かない。
- 同じオブジェクトのブロックの間に空行を1つ。最上位のオブジェクトの最後のブロックのあとに空行を1つ。
- 値: 整数は10進。`float` / `double` は `std::to_chars` の最短表現。`bool` は `true` / `false`。配列は `[<要素数>]` のあとに要素を `,` で区切る(空白を入れない)。
- 文字列(値と、文字列配列の要素)のエスケープ: `\` → `\\`、改行 → `\n`、復帰 → `\r`、`,` → `\,`、それ以外の 0x00〜0x1F(タブ 0x09 を除く)→ `\xHH`(16進2桁、大文字)。バイト単位で行う。先頭や末尾の空白はそのまま書き、読むときも削らない。
- 読むときは、文字列の値の中のエスケープされていない `,` をそのまま `,` として受け取る(配列では区切り)。`\xHH` の16進は大文字も小文字も受け付ける。

### v2 の読み方(数と空行とインデントで決まる)
- ブロックは、空行、インデントが 2×d より浅い行、ファイルの終わりのどれかで終わる。
- オブジェクトはヘッダーのブロック数だけブロックを読む。最後以外のブロックのあとは、空行を1つ読み飛ばす(無ければ失敗)。
- 行のキーをヒントから探し、ヒントの型で値を読む。ネストしたオブジェクトは再帰で読む。

### v1 の読み方(1行目に `#Version` が無いファイル)
今の読み方をもとに、読めていたものは同じ結果になるようにする。
- ヒントの順に行を読む。行のキーが今のヒントと違えば、後ろのヒントから探す(今と同じ)。
- 空行: ブロックの先頭なら読み飛ばす。途中ならブロックの終わり(空行は消費しない)。ファイルの終わりは、空行と同じに扱う。
- 後ろのヒントにも無いキー: 最上位のオブジェクトなら失敗。ネストしたオブジェクトならブロックの終わり(その行は消費しない)。
- 最上位のオブジェクトのブロックのあとに空行があれば、1つ読み飛ばす。
- 配列は `, ` 区切りで、要素の先頭の空白1つを取り除く。エスケープは解釈しない(今と同じ)。
- 数値として読めない値は 0 にする(今と同じ)。

## エラー処理と境界条件
- ファイルを開けない: `false`。保持しているデータは変えない(今と同じ)。
- 解析の失敗: `false`。保持しているデータは変えない(今は、消したうえで途中までの内容が残る)。`std::cerr` に1行出す(今と同じ扱い)。
- v2 で失敗にするもの: ヘッダー行の形が違う / 数が負 / インデントが 2×d でも、それより浅くもない / ヒントに無いキー / 同じブロックに同じキーが2回 / 数値の後ろに余分な文字 / `bool` が `true` でも `false` でもない / 配列の要素数が合わない / 知らないエスケープ、末尾が `\` 1つ / ブロックの間の空行が無い / オブジェクトが `#ObjNum` より少ない / 最後のオブジェクトのあとに空行以外の行がある / `#Version` が 2 以外。
- v1 で失敗にするもの: `[` `]` `{` `}` `:` が見つからない行(今は例外)、オブジェクトのヘッダー行が `#ObjNum` より少ない。
- 境界: オブジェクト0個、ブロック0個のオブジェクト、キーが1つも無いブロック、要素0個の配列、空文字列、空文字列だけの文字列配列は、v2 で読み戻せる。
- 配列の要素数やブロック数を、そのまま `reserve` に使わない(壊れたファイルで巨大な確保をしない)。
- ネストの深さは 64 まで(最上位のオブジェクトのブロックが深さ 1)。超えるファイルは v1 でも v2 でも読み込み失敗。超えるデータを書こうとしたら `Write` は `false`。
- `Write` は、ヒント文字列を分解できないオブジェクトがあれば `false`。
- ネストしたオブジェクトの名前はテキストに書かない(今と同じ)。読み戻した名前は空になる。

## 重要な設計判断
- 版数つきの新形式にする: エスケープを足すと `\` の意味が変わる。版数の無いファイルを今までどおり読めば、既存のデータ(Windows のパスなど)が化けない。(常にエスケープする案は、既存ファイルが化けるので採らない。エスケープしない案は、保存できないデータが残るので採らない。)
- v2 と v1 で読み方を分ける: v2 は厳密に読み、壊れたファイルを確実に検出する。v1 はインデントが信用できない(`cpon_object::operator[]` で作ったネストのブロックは、インデントが浅く書かれている)ので、今の読み方を保つ。(1つのゆるい読み方で両方を読む案は、外側と内側に同じ名前のキーがあるとブロックの終わりを取り違えるので採らない。)
- v1 の読み方にも、空行とネストの直しを入れる: 旧バージョンが書いたのに読めなかったファイルの多くが読めるようになる。今読めているファイルの結果は変わらない。
- インデントは書き込み時の深さで決める: `m_NestedLevel` は `AddObject` や `operator[]` のあとで実際の深さとずれることがあり、v2 の厳密な読み方と合わなくなる。
- テキストの処理を `cpon` から内部用のファイルに出す: 公開ヘッダーから実装の詳細を消す。`cpon.cpp` はテキスト部分が半分以上を占めている。

## 制約・前提
- C++20、MSVC(v143 / v145)、Win32 / x64。`/W4` で警告を出さない。
- ソースは Shift-JIS(CP932)、改行は CRLF。新しいファイルも同じにする。新しいコメントは英語(ASCII)で書く。
- ファイルはテキストモードで開く(今と同じ)。エスケープはバイト単位なので、Shift-JIS の2バイト目が `\`(0x5C)の文字(「表」など)は、ファイル上で `\` が1つ増えて見える。読み戻した値は元と同じ。
- ソースを足すので、`CPON/CPON.vcxproj`、`CPON/CPON.vcxproj.filters`、`CPON/Test/build_test.bat` に `cpon_text.cpp` を足す。
- リリースは別作業。形式が増えるので、版は 1.5.0 にする。
- 規約スキル: cpp-conventions

## テスト方針
- `CPON/Test/test_binary.cpp` に足す。実行は `CPON\Test\build_test.bat`(Debug / Release とも `ALL TESTS PASSED`)。
- v2: 既存の全ケース(`MakeCases` を含む)を、テキストの往復でも確かめる。上の「境界」と、成功の条件の5つを足す。
- v1: 旧形式の内容を文字列でファイルに書き、読んだ値を確かめる(`CPON/output.cpon` と同じ形、ネストの複数ブロック、末尾キーの欠け)。
- 壊れたファイル: 「v2 で失敗にするもの」「v1 で失敗にするもの」を1つずつ書き、`false` が返ることと、読む前のデータが残っていることを確かめる。
